# Assumptions and Architectural Decisions Log

This document records key decisions, assumptions, and conflict resolutions made during the design and construction of the ORCA platform.

---

## 1. Conflict Resolutions & Order of Authority

As established in `00-CONTEXT-BLOCK.md`, the strict hierarchy of authority when files disagree is:
1. **1st: `prompts/00-CONTEXT-BLOCK.md`** (binding rules: S1–S10 safety and honesty, P1–P12 working protocol, reporting format). Overrides everything.
2. **2nd: The TASK file for the current target** (`TASK-<n>-*.md`).
3. **3rd: Technical spec docs** (`spec-docs/*` / `docs/*`).
4. **4th: Course or assignment material** (`Technology and Sustainability Mini Project Guidelines.pdf`, BTLAP, PPTX). Wins on deliverables, formats, and rubric items.
5. **5th: Older or superseded attempts / prompts**: Used only as forensics to learn what failed; otherwise ignored.

### 1.1 Academic Deliverables vs. Production Software
- **Context:** The Bennett University course guidelines in `C:\Users\thetu\Documents\Bennett Study\SEM 1\Sustainability\Technology and Sustainability Mini Project Guidelines.pdf` require a 9-chapter academic report, presentation slides, BMC, video demonstration scripts, and LinkedIn post. The technical docs describe a production web service.
- **Decision:** As governed by Rule 4 vs Rule 3, the project builds the complete working full-stack production software in `frontend/`, `backend/`, and `infra/`, AND delivers the full academic course deliverables in `deliverables/`.

### 1.2 Frontend Architecture & Navigation Model
- **Context:** React Router v7 with lazy route modules and standard deep linking vs simple landing page.
- **Decision:** All routes are nested under `RootLayout` (`<Outlet>`) in `router.tsx` to support global toast/banner providers while avoiding context lifecycle breaks. Dedicated client-side routes will be implemented for all expected public and protected pages (including ports directory, compare, how-it-works, methodology, about, status, game, and error).

### 1.3 Risk Assessment Authority
- **Context:** Generative AI models are prone to hallucination and cannot be trusted with safety-critical decisions that affect human lives at sea.
- **Decision (Rule S1):** Purely deterministic rules engine (`backend/apps/risk/rules.py`). Pure Python functions with zero database, zero network, zero LLM, and zero clock reads. The LLM only handles intent routing and natural language explanation generation. All numeric assertions generated by the LLM are checked by `agents/validators.py` against structured tool results.

## 2. Infrastructure & Local Development Assumptions

### 2.1 Domain Resolution via `localtest.me`
- **Decision:** Local development relies on `app.localtest.me:5173` and `api.localtest.me:8000`. `*.localtest.me` is a public DNS wildcard that resolves to `127.0.0.1`. This allows standard session cookies with `Domain=.localtest.me` to be shared between frontend and API without requiring manual `hosts` file modification on Windows.

### 2.2 Docker & GeoDjango Dependencies
- **Decision:** GeoDjango requires GDAL, GEOS, and PROJ libraries. While Python 3.14 on the host executes Django manage commands and unit tests, the full containerised stack (`infra/docker-compose.yml`) provides PostGIS 16+ and Redis. When Docker Desktop is not actively running, manage check and test commands execute natively using SQLite / spatial mock configurations.

### 2.3 Cloudflare Turnstile Development Keys
- **Decision:** Testing uses Cloudflare's published dummy site keys:
  - Site Key: `1x00000000000000000000AA` (Always passes)
  - Secret Key: `1x0000000000000000000000000000000AA`
  - Site Key: `2x00000000000000000000AB` (Always blocks / fails)

### 2.4 LLM Fallback Provider
- **Decision:** `LLM_PROVIDER=template` is enabled by default so the entire application, test suite, and offline mode function without requiring paid API keys. Production supports `gemini` and `anthropic` providers configurable via environment variables.

### 2.5 Risk Thresholds as Development Placeholders
- **Decision (Rule S10):** The risk thresholds defined in `apps/risk/thresholds.py` are explicitly documented as development placeholders and marked with UI banners ("Demo data / Placeholder thresholds: Consult official INCOIS/IMD forecasts before venturing to sea").
